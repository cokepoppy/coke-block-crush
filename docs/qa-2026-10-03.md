## 自动反馈回归补充

本轮新增 `npm run test:feedback`：先跑引擎单测和生产构建，再用 Playwright 在 `390 × 844` Chromium 视口执行浏览器回归。自动检查 Level 1/4/7 稳定帧、实现截图基线、可见控件放置、重叠无效输入、重开状态、清行与苹果计数；清行动画还检查光束、飞果和棋盘光晕的 CSS 动画名/时长，并在 1.05 秒后确认特效清空。运行时监控页面异常、非预期 HTTP 错误和资源请求失败。浏览器音频检查确认首次用户操作前未创建 AudioContext，操作后 Web Audio 进入 running 状态且确实排程音乐声部、接受按钮/落块/清除/收集提示音，并验证音乐和音效开关会影响对应信号路径。

对同一 Level 1 参考图裁切 `575 × 833`，把本地游戏按源图宽度 `575px` 捕获，并用 `pixelmatch` 阈值 `0.16` 比较；遮罩视频中央播放键 `105 × 110` 与触点 `52 × 52`（共 14,254 像素）。头像、进度条和宝箱尺寸按源图校准后，公开回归 fallback 的差异从初测 **6.54%** 降至 **6.15%**；加载本机忽略目录中的候选原作图标包后为 **5.71%**。两者都低于本次 8% 门槛，但仍不是像素级通过。差分图、叠图、实际图和 JSON 报告保存在 Git 忽略的 `test-results/feedback/`；更新的三张提交 PNG 是本地实现回归基线，和源游戏参考帧分开保存。

本机研究素材模式另跑 `BLOCK_CRUSH_USE_LOCAL_REFERENCE=1 npm run test:e2e -- --grep 'browser audio'`，确认 `button/place/clear/apple/win` 五个本地候选 WAV 都能被浏览器解码加载。原作包的当前候选索引没有确认到背景音乐；游戏 BGM 使用程序合成循环。自动化不会从浏览器硬件回环录音，也不判断音色、响度、旋律或循环接缝；原作音乐/音效一致性仍需取得带原声参考并做听辨/波形比对。
